01Mission

Moderniser l’interface de l’outil Reflex

Une application existe déjà en ligne de commande, mais elle n’est pas facile à utiliser.

L’application appelle des interfaces : des scripts qui récupèrent certaines valeurs dans une base de données cliente. Elle sert à exporter des données précises au format CSV ou Excel.

05Difficulté & solution

Une application qui se fige

Lorsqu’on appelle une interface, l’application traite beaucoup de données et se fige, car elle ne peut exécuter qu’une tâche à la fois.

Solution : les threads

Les données passent par un signal qui envoie les informations à l’interface. Elle les récupère et échange par ce « tunnel ».

Limite d’un seul thread

Quand le même thread est appelé plusieurs fois pour différentes interfaces, les informations ne concordent plus et les données récupérées sont mélangées.

Multi-threading

J’ai mis en place un multi-threading avec un signal par interface. Plusieurs tâches s’exécutent en parallèle, ce qui améliore les performances de l’application.

05Difficulté & solution

Récupérer les données par API

Le plus simple pour récupérer les données est d’utiliser des API, en filtrant les données directement dans l’URL.

La limite de requêtes

Le serveur de développement n’impose aucune restriction sur le nombre de requêtes. Le serveur de production en autorise 5 au maximum, alors que le chargement de la page en effectuait 13.

Solution

Je n’effectue plus qu’une seule requête globale, sans filtre, pour récupérer toutes les informations nécessaires. Le tri et le filtrage sont ensuite réalisés côté client en JavaScript.
